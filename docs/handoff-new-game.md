# Памятка для нового чата: как мы делали «Пристав: смена»

Вставь этот файл первым сообщением в новый чат вместе с описанием новой игры. Скиллы (grilling, domain-modeling и др.) подключены к аккаунту глобально и в новом чате уже есть.

## Как со мной работать (правила владельца)
- Отвечай по-русски, коротко и по делу.
- Новая крупная идея начинается с раунда вопросов (скилл grilling): нумерованные ❓ с рекомендацией ➡️, потом ждать ответа. Мелкие правки и баги делать без опроса.
- Термины и решения вести в `GLOSSARY.md` и `CLAUDE.md` проекта сразу.
- Проверять сделанное (синтаксис, автотесты, прогон в браузере) и честно писать, что не проверено на телефоне.
- Коммиты: `git -c user.name=dev -c user.email=cas1no21@outlook.com commit ...`, строки об авторстве не добавлять.
- Картинки через внешние сервисы: без женственных и агрессивных образов (строгая модерация, у владельца уже были блокировки). Графику лучше рисовать кодом.
- Юмор и сатира допустимы, 16+, без жестокости и без пропаганды.

## Технический рецепт (то, что уже отработано)
- **Одна HTML-игра без сервера:** исходники в `src/` (`head.html`, `data.js`, `gen.js`, `career.js`, `music.js`, `cloud.js`, `engine.js`), сборка `node tools/build.mjs` склеивает их в `index.html` (для сайта) и `pristav.html` (для Artifact). Собранные файлы руками не править.
- **Графика:** canvas 96x72 с `image-rendering: pixelated`, всё рисуется прямоугольниками в коде (`R(x,y,w,h,цвет)`), значки 16x16 списками прямоугольников в `ICONS`. Меню-кабинет: предметы-кнопки поверх canvas (`hotspots`).
- **Звук и музыка:** WebAudio без файлов (`Snd`, `Music`), запуск только после первого касания.
- **Проверка:** `node tools/check.mjs 200` (сборка, `node --check`, проверка данных, генератор на 800 случаев, 200 случайных прохождений в vm с заглушками DOM). Ручной прогон в браузере через локальный `python -m http.server`.
- **Аккаунты и облако:** Supabase (бесплатный). Чистый `fetch`, anon-ключ публичный, защита политиками RLS (`supabase/schema.sql`). Вход по логину: в Auth служебная почта `<логин>@pristav.game`, настоящая почта в `profiles`, подтверждение почты выключено. Таблицы: `profiles`, `saves` (JSON сохранения), `scores` (через функцию `submit_score`). Сброса пароля по почте нет.
- **Публикация:** GitHub (репозиторий `JoyCas1no/pristav`), GitHub Pages из `main`, корень; после `git push` сайт обновляется за ~1 минуту. Адрес: https://joycas1no.github.io/pristav/
- **Статистика игроков:** SQL-запрос в Supabase SQL Editor (только чтение, без почт), через Chrome с расширением Claude.

## Подводные камни
- Создавать аккаунты и вводить пароли за владельца нельзя: он входит сам (GitHub, Supabase), потом я работаю в его сессии через Chrome.
- Поиск токенов и учётных данных на диске запрещён классификатором: не пытаться.
- Страница Supabase падает из-за автоперевода Chrome (отключить перевод для сайта); ключ `service_role` не копировать и не хранить.
- Хуки GateGuard требуют перед первым созданием или правкой файла перечислить факты и слова пользователя, затем повторить вызов. Если правка прошла частично, проверить файл перед повтором.
- Файл, переписанный скриптом, нужно перечитать перед правкой инструментом.
- Тестовые аккаунты из проверок удалять в Supabase → Authentication → Users.

## Что делать в новом проекте
1. Создать папку, `git init`, `CLAUDE.md` с правилами выше.
2. Раунд вопросов по новой игре.
3. Взять каркас сборки (`tools/build.mjs`, `tools/check.mjs`) и при необходимости модули `cloud.js` и `music.js` из этого проекта.
4. Если нужны аккаунты: новый проект в Supabase (или тот же с другими таблицами), схему писать по образцу `supabase/schema.sql`.
